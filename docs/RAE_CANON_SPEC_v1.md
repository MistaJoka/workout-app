# RAE — LOCKED CHARACTER CANON v1.0

## 0. Purpose

This file exists to prevent **identity drift, hallucinated anatomy, accessory loss, style substitution, proportion drift, and silent redesign** when Rae is generated by AI, illustrated, animated, converted to 3D, or used in application assets.

Rae is an **existing character**. Generation tasks are rendering tasks, not character-design tasks.

> **Core law:** Preserve Rae first. Apply the requested pose/action second. Everything else is subordinate.

---

# 1. Canon authority hierarchy

When references disagree, resolve them in this exact order:

1. **`RAE_SOURCE_OF_TRUTH_v1.png` — PRIMARY VISUAL AUTHORITY**
   - Original supplied character bible.
   - Defines Rae's actual visual identity, proportions, face, hair, ears, body silhouette, outfit, tattoo, accessories, palette relationships, and pixel-art language.
   - SHA-256: `2e3d6ca6ae3b0f4a320bf240480648f0b2b308a625b3f9be9b4e0e8b35b2ec83`

2. **This document — PRIMARY SEMANTIC AUTHORITY**
   - Encodes what must remain invariant across generations.
   - Clarifies ambiguous or easily hallucinated details from the image.
   - Does **not** override visible facts in the primary source image.

3. **`RAE_HARDENED_REFERENCE_v1.png` — SECONDARY SUPPORTING REFERENCE**
   - Reinforces critical locks and rejection rules.
   - Useful as an auxiliary reference only.
   - SHA-256: `7ee2c314b960330147243b3191898c1b3f7d5437103490386ea2757b28ce03ab`

   - May demonstrate valid poses/expressions.

   - Have **zero authority** over Rae's identity.

### Conflict rule

If any generated image, secondary reference, prompt, animation, model, or document conflicts with the primary source image, **the primary source image wins**.

### No recursive drift

Never use a newly generated Rae image as the sole reference for another Rae generation. Always anchor back to the primary source image and this specification.

# 3. Critical identity invariants

These are **hard locks**. A generation violating any one is rejected.

## 3.1 Face

Preserve the facial identity visible in the source:

- Same overall face shape.
- Same eye scale and placement relationship.
- Same nose scale and shape relationship.
- Same mouth/lip relationship.
- Same brow placement and general shape.
- Warm brown skin tone consistent with the source.
- Adult facial proportions.
- Friendly, confident visual read.

### Never

- Replace Rae with a different face.
- Shift toward a generic anime face.
- Make her childlike or teen-coded.
- Change ethnicity-coded facial identity.
- Lighten or darken skin substantially.
- Introduce photorealistic skin rendering in a pixel-art production asset.

---

## 3.2 Hair

Hair silhouette is identity-critical.

**Required:**

- Dark, dense, tightly curled hair.
- Large gathered curly/updo mass as shown in the source.
- Loose curls framing the face.
- Similar visible volume from front, side, and rear.
- Hair must integrate naturally around the bases of the bunny ears.

**Forbidden:**

- Straight hair.
- Loose long waves replacing the canonical style.
- Ponytail substitution.
- Afro substitution that materially changes the silhouette.
- Braids/locs unless a future canon version explicitly authorizes them.
- Shrinking the hair mass merely to simplify animation.

---

## 3.3 Bunny ears — CRITICAL ANATOMY LOCK

Rae has **exactly two bunny ears and zero human ears**.

Required geometry:

- Exactly `2` bunny ears.
- Emerge from the upper head/hair mass.
- Semi-upright orientation.
- Long rabbit-ear silhouette.
- Warm outer ear coloration consistent with source.
- Pink inner ear.
- Relative length, width, spacing, and tilt should remain consistent with the source.

### Absolute prohibitions

- **NO HUMAN EARS.**
- No extra bunny ears.
- No missing bunny ear.
- No cat ears.
- No fox ears.
- No detachable headband interpretation.
- No ear duplication caused by hair or perspective.
- No four-ear human+bunny anatomy.

If perspective hides one ear, the hidden ear still exists anatomically; do not redesign the character.

---

Rae wears:

- Round glasses.

Glasses are a **mandatory signature feature** unless a specific future canon variant explicitly removes them.

Forbidden:

- Square frames.
- Rimless glasses.
- Silver/black frames.
- Sunglasses.
- Missing glasses.

## 3.6 Tattoo

Rae has exactly one canonical tattoo:

- Lotus design.
- Located on the **LEFT collarbone**.
- Slightly under/adjacent to the left top strap as established by the source.
- Dark ink appearance consistent with the source.

### Tattoo lock

- LEFT means **Rae's anatomical left**, not the viewer's left.
- Mirror-flipping an image does not move the tattoo anatomically.
- Do not duplicate the tattoo.
- Do not place it on the right collarbone.
- Do not add arm, chest, shoulder, neck, back, face, or leg tattoos.
- Do not substitute another flower or symbol.

---

## 3.7 Body proportions

Canonical body read:

- Adult.
- Curvy.
- Strong.
- Athletic.
- Approx. **7.5 heads tall** in the character bible's full-body presentation.
- Broad/strong upper body without bodybuilder exaggeration.
- Defined arms.
- Full hips.
- Full thighs.
- Strong legs.
- Narrower waist relative to hips and shoulders.
- Stable silhouette across front, 3/4, side, 3/4 rear, and rear views.

The source turnaround is the authority for relative proportions.

### Never

- Slim Rae into a generic fitness-model body.
- Make her petite.
- Make her extremely muscular/bodybuilder-like.
- Inflate chest/hips beyond the source.
- Shrink thighs to simplify poses.
- Use child/chibi proportions for normal gameplay assets.
- Change height from frame to frame.
- Change body composition during animation.

---

## 3.8 Tail

Rae has:

- Exactly one bunny tail.
- Small size.
- Round/fluffy shape.
- Brown coloration consistent with source.
- Correct lower-back placement.

Forbidden:

- Long rabbit tail.
- Cat/fox tail.
- Multiple tails.
- Oversized pom-pom tail.
- Tail attached to clothing instead of anatomy unless visually indistinguishable and explicitly required by implementation.

When the tail is occluded by camera angle or body pose, do not force it into visibility.

# 5. Canonical visual style

Rae's production style is:

- High-bit pixel art.
- GBA/SNES-inspired visual language.
- Clean, deliberate pixel clusters.
- Strong readable silhouette.
- Controlled shading.
- Warm, friendly, expressive presentation.
- Sufficient detail to preserve face/accessories at gameplay scale.
- Cohesive palette relationships.
- No accidental anti-aliased painterly edges when producing final pixel assets.

## Style hierarchy

1. Identity readability.
2. Silhouette readability.
3. Pose readability.
4. Pixel-cluster cleanliness.
5. Detail.

Do not sacrifice Rae's identity to preserve a requested stylistic gimmick.

### Forbidden style drift

Unless specifically requested as a non-canon study:

- Photorealism.
- 3D-render appearance presented as canonical pixel art.
- Generic anime redesign.
- Chibi redesign.
- Western comic redesign.
- Vector-flat redesign.
- Painterly illustration.
- Hyper-detailed realistic skin/hair.
- Different pixel-art franchise imitation that materially changes Rae.

# 8. Pose and exercise generation contract

Every exercise request is interpreted as a **delta against canon**.

## Immutable layer

The following do not change because of a pose:

- Identity.
- Body proportions.
- Species anatomy.
- Hair identity.
- Ear count.
- Glasses.
- Necklace.
- Tattoo identity/location.
- Outfit design.
- Skin tone.
- Pixel Bloom style.

## Mutable layer

A generation may change only what the task requires:

- Joint angles.
- Limb position.
- Torso rotation/flexion.
- Weight distribution.
- Facial expression.
- Camera angle.
- Occlusion.
- Cloth deformation caused by movement.
- Hair/tail secondary motion consistent with physics.

### Exercise anatomy rule

For workouts, biomechanical pose correctness must be achieved **without changing Rae's body design**.

Example:

`Squat` means bend hips/knees/ankles and reposition torso/arms as needed. It does **not** mean slim her thighs, alter hip width, remove accessories, redesign shoes, or change ear anatomy.

# 10. Camera and mirroring rules

Camera angle changes visibility, not identity.

Horizontal mirroring is dangerous because Rae has an asymmetric canonical tattoo.

If an image is mirrored for animation/gameplay:

- Rae's anatomical LEFT-collarbone tattoo must remain logically left.
- If using a literal mirrored sprite for performance, document that it is a rendering shortcut and decide whether tattoo asymmetry must be corrected in the mirrored asset.

Do not silently reinterpret viewer-left as anatomical-left.

# 14. Generation acceptance gate

A generated asset is **not Rae** until it passes this gate.

## Critical blockers — any failure = REJECT

- [ ] Same recognizable Rae facial identity.
- [ ] Adult appearance preserved.
- [ ] Skin tone consistent with primary source.
- [ ] Curvy/strong/athletic canonical body proportions preserved.
- [ ] Canonical hair silhouette preserved.
- [ ] Exactly two bunny ears.
- [ ] Zero human ears.
- [ ] Round gold glasses present.
- [ ] Gold `A` necklace present when anatomically visible.
- [ ] Lotus tattoo is on Rae's anatomical LEFT collarbone when that area is visible.
- [ ] No additional tattoos.
- [ ] Canonical outfit construction preserved.
- [ ] Canonical black/white sneaker design preserved when visible.
- [ ] No unauthorized species traits or accessories.

## Style and production checks

- [ ] High-bit Pixel Bloom pixel-art language preserved.
- [ ] Silhouette remains readable at intended size.
- [ ] Pose reads correctly without anatomy breakage.
- [ ] No accidental extra/missing fingers where visible enough to judge.
- [ ] No fused limbs or impossible joints.
- [ ] Hair/ears/tail do not intersect anatomy unnaturally.
- [ ] Perspective is internally coherent.
- [ ] Palette remains within the canonical visual family.
- [ ] No frame-specific redesign if part of a sequence.

### Decision

- **PASS:** all critical blockers pass and no material production defect exists.
- **REJECT:** any critical blocker fails.
- **REGENERATE/REPAIR:** identity passes but pose/rendering contains correctable production defects.

Never approve a visually attractive output that fails a critical identity lock.

# 15. Drift audit for animation batches

For a multi-frame batch, compare every frame against **Frame 0 + source-of-truth**, not merely against the previous frame.

Audit these measurements/relationships:

1. Head-to-body ratio.
2. Shoulder-to-head width ratio.
3. Hip-to-shoulder relationship.
4. Thigh/calf thickness.
5. Ear length relative to head.
6. Ear spacing and root position.
7. Hair bounding silhouette.
8. Glasses diameter relative to eye/face.
9. Pendant scale.
10. Tattoo anatomical position.
11. Shoe size relative to leg.
12. Core palette relationships.

This prevents cumulative frame-to-frame drift.

# 16. Dataset hygiene rules

AI consistency improves with **clean authority**, not uncontrolled reference volume.

## Approved reference set

Only add an image to the approved Rae reference set if:

1. It was checked against this canon.
2. Every critical blocker passes.
3. It adds a useful new pose/angle/expression not already represented.
4. It does not introduce a contradictory interpretation.
5. Its approval is deliberate and versioned.

## Never ingest automatically

Do not automatically add generated outputs to:

- fine-tuning datasets,
- LoRA datasets,
- embedding/reference libraries,
- pose libraries,
- future prompt examples,

until they pass the acceptance gate.

One bad image can become a repeated hallucination if promoted into the training/reference loop.

# 17. Future 3D translation rules

If Rae is converted to a rigged 3D model, the **3D mesh becomes an implementation of this canon, not a replacement for it**.

The 3D model should lock:

- Canonical body proportions.
- Canonical head and facial relationships.
- Hair silhouette.
- Exactly two bunny ears / zero human ears.
- Tail location and volume.
- Glasses geometry.
- Necklace and `A` pendant.
- Left-collarbone lotus tattoo UV/decal placement.
- Outfit construction.
- Shoe silhouette.

Once a validated 3D model exists, exercise generation should preferentially be represented as **rig/skeleton coordinates + animation clips**, which is substantially more deterministic than re-generating Rae independently for every frame.

# 18. Change control

This file is **LOCKED CANON v1.0**.

A production output cannot silently modify canon.

Any intentional identity change requires:

1. Explicit owner decision.
2. New source-of-truth visual if applicable.
3. New semantic specification version.
4. Updated hash manifest.
5. Regression review against existing production assets.
6. Version increment (`v1.1`, `v2.0`, etc.).

### Version semantics

- Patch (`1.0.1`): typo/clarification; no visual identity change.
- Minor (`1.1`): approved additional canon detail/variant that does not replace identity.
- Major (`2.0`): intentional visual identity redesign.

Generated model behavior is never itself justification for changing canon.
